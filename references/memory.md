# 记忆格式与记录器

## 目的

只记录本次任务中**已复现或已核实**、且可能跨项目复用的新失败机制。它不是项目 bug 列表，也不是平台经验仓库。

新包不预置任何避坑条目。记忆从空白开始，由实际使用逐步积累。

## 两类记忆

- **本地记忆**：`PITFALLS.local.md`。安装后使用，首次记录时自动创建，升级时保留。
- **仓库记忆**：`PITFALLS.md`。仅维护本仓库时使用；不存在时由记录器创建空白模板。

默认优先本地。判断顺序：

1. 已存在 `PITFALLS.local.md`；
2. 技能位于 `skills/` 目录下；
3. 技能根目录有 `.git` 且用户指定仓库范围；
4. 否则使用本地。

## 条目格式

```text
YYYY-MM-DD | 标签 | 触发场景 | 错误做法 | 正确做法 | 验证方式
```

六个字段都必须非空，不能包含换行或 `|`。触发场景写“什么时候会复发”，不写长篇叙事。

## 标签

建议至少包含：

- 宿主导航：`host:qwen-code`、`host:generic`；
- 模型标签：`model:qwen`、`model:gpt`、`model:qwen`、`model:generic`；
- 阶段：`scope`、`build`、`test`、`security`、`report`；
- 机制大类：`false-green`、`injection`、`permission`、`encoding`、`migration` 等。

标签用于检索，不是永久分类。模型或宿主行为变化后，调整标签不要删除历史。

## 查重与父条目

- 六个字段完全相同：不追加；日期较新时只更新原条目日期。
- 同一大类下的新失败机制：新增条目，并用 `--parent` 指向已有条目，例如 `TEST-02`。
- 新机制不能因为“看起来相似”就被合并；只有机制相同才去重。

## 只追加

- 不删除旧条目。
- 过时条目标注 `[已过时]` 并说明原因。
- 升级技能时保留 `PITFALLS.local.md`，不要覆盖。

## 记录器

```text
python scripts/record_pitfall.py \
  --tag "host:qwen-code,model:qwen,test" \
  --trigger "..." \
  --wrong "..." \
  --right "..." \
  --verify "..." \
  --parent TEST-02
```

可选参数：

- `--scope auto|local|repo`
- `--root <skill-root>`
- `--date YYYY-MM-DD`
- `--dry-run`

记录器只写技能根目录下的 `PITFALLS.local.md` 或 `PITFALLS.md`，拒绝：

- 根目录指纹不符；
- 写到根目录之外；
- 空字段、换行、`|` 分隔符；
- 常见密钥、个人绝对路径、邮箱、私有 IP；
- UTF-8 BOM 或不可信编码。

写入失败时报告待记录条目，不中断审计，不改成不安全的 shell 重定向。

## 什么值得记录

- 假绿：命令失败却报通过、空测试集、跳过作业被当成通过；
- 静默回退：配置为空却回落到不安全默认值；
- 不可回滚：发布或迁移没有可用回退；
- 验证方法本身有缺陷：扫描器漏检、正反例不成立；
- 跨项目可复用的权限、注入、编码、路径、并发或资源问题。

## 什么不记录

- 单个项目里的普通业务 bug；
- 目标项目原文、未脱敏日志、客户数据；
- 密钥、令牌、个人绝对路径、邮箱、私有 IP；
- 未复现、未核实、只靠猜测的“坑”；
- 对某个模型或宿主的刻板印象。

## 提升为规则

同一机制出现两次以上，优先提升为：

- 核心不变量；
- 宿主适配规则；
- 自动化测试或 CI 检查；
- 模型补偿控制。

日志不是终点；能自动化的失败机制不要只留在记忆里。

## 报告结果

最终报告附：

```text
记忆：新增 N 条，重复 M 条（<文件>）
```

或：

```text
记忆：无新坑
```

写入失败时写“待记录”，并列出最小必要信息。
