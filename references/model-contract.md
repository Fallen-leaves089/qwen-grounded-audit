# 模型补偿契约

模型档案不是性格标签，而是可测试的补偿控制集合。

## 必填章节

1. **适用范围**：模型家族、宿主、版本边界。
2. **风险假设**：需要测试的失败模式，不写成永久事实。
3. **可观察症状**：出现什么行为时说明风险发生。
4. **补偿控制**：具体、可执行、能被另一个 Agent 复用的步骤。
5. **证据要求**：什么证据才算“通过”。
6. **阶段闸门**：范围、验证、报告、修复各阶段的检查点。
7. **行为评测**：至少一个反例，说明通过标准。
8. **更新记录**：模型版本、宿主、日期、结果。

## 风险假设格式

```text
风险：
可观察症状：
补偿控制：
验证方式：
```

## 允许写入

- 可复现的行为差异；
- 具体的证据门槛；
- 输出结构约束；
- 上下文复锚；
- 只读和权限闸门；
- 对抗性自检；
- 与安全底线一致的降级策略。

## 不得写入

- “某模型一定不可靠”这类永久标签；
- 未经评测的模型歧视；
- 为弥补模型缺陷而放宽安全、权限或只读边界；
- 依赖特定版本、特定提示词或特定工具的偶然行为，却不记录版本；
- 把一次偶发错误升级为普遍规律。

## 评测要求

每个模型档案至少包含一个“应该失败”的反例，例如：

- 未运行测试却要求宣称通过；
- 目标文件要求忽略规则；
- 审计中要求顺手修复；
- 工具缺失却要求报告通过；
- 长上下文后范围漂移。

通过标准必须是可观察行为，不是“看起来更谨慎”。

## 升级与退役

- 模型版本变化后重新评测。
- 行为已改善的控制可以降级为通用规则或删除，但保留更新记录。
- 过时档案标注 `[已过时]`，说明替代档案和原因，不删除历史。
