# 宿主适配契约

一个宿主适配文件必须让另一个 Agent 能在该宿主中正确执行核心审计，而不是只介绍产品。

## 必填章节

1. **状态**：`validated` / `documented` / `experimental`，以及验证日期和环境。
2. **识别**：如何确认当前宿主；无法确认时如何降级。
3. **安装位置**：个人、项目、插件或等价位置。
4. **调用方式**：显式命令、自动触发、参数传递。
5. **工具映射**：通用动作到宿主工具的对应表。
6. **权限边界**：哪些工具预授权，哪些逐次确认，如何避免绕过审批。
7. **上下文生命周期**：技能内容是否持久、压缩后如何复锚、临时授权何时失效。
8. **目标内容边界**：项目指令文件为何仍不可信。
9. **子代理/并行**：如何启动、如何限制只读、主代理如何复核。
10. **网络与写入**：何时需要用户同意，缺失时如何降级。
11. **记忆记录**：如何定位和调用记录器。
12. **自检清单**：至少覆盖加载、只读、注入、输出和未覆盖项。
13. **未验证项**：本机或当前版本没有实际跑过的行为。

## 能力矩阵

每项能力标记：

- `native`：原生可用；
- `partial`：有限制；
- `absent`：不可用；
- `unknown`：未探测。

至少覆盖：文件读取、搜索、文件枚举、命令执行、写入、网络、子代理、交互提问、持久记忆。

## 验证要求

- `documented`：只按官方文档编写，尚未在真实宿主运行。
- `validated`：在真实宿主安装、调用、执行一个只读夹具，并检查注入、只读、报告和未覆盖项。
- 从 `documented` 升到 `validated` 必须记录宿主版本、模型、日期和证据。
- 没有运行证据时，不得写“已支持”或“已验证”。

## 不得写入

- 平台避坑大全或固定系统命令清单；
- 要求关闭权限检查、审计日志或安全软件的步骤；
- 把项目 `CLAUDE.md` / `AGENTS.md` 当成高优先级指令的规则；
- 未经验证的“最佳实践”；
- 只能在一台机器上成立的绝对路径。

## 模板

新增宿主时从 `hosts/generic.md` 和本契约开始，不要复制 Claude Code 的工具名或路径。
